## Backend Fixes

### B1. Fix stock leak in `orders/views.py` (HIGH)

**Problem:** Stock is decremented inside the items loop *before* the order is created. If all 5 order-number retries fail, the view returns a 500 response (not an exception), so `@transaction.atomic` commits the stock deductions while no order exists.

**Fix:**
- In the first loop, only validate stock and build an `order_items` list.
- Remove the `F()` decrement + `save()` + `refresh_from_db()` from the first loop.
- After the order is successfully created, create `OrderItem` rows and decrement stock with a single `ProductVariant.objects.filter(id=...).update(stock_quantity=F(...) - qty)` call per item.

### B2. Tighten exception handling in `orders/views.py` (W1)

**Fix:** Change `except Exception:` on order-number collision to `except IntegrityError:` (import from `django.db`).

### B3. Fix Arabic typo in `orders/signals.py` (W2)

**Fix:** "رق" → "رقم" in the order-confirmation email subject.

### B4. Slug-based storefront filters in `products/views.py` (F3a)

**Fix:** Change `ProductViewSet.filterset_fields` from PK-based to slug-based:

```python
filterset_fields = {
    'categories__slug': ['exact'],
    'brand__slug': ['exact'],
    'gender': ['exact'],

}
```

### B5. Add filters/search to `AdminProductViewSet` (F4 + F5)

**Fix:**

## Frontend Fixes

### F1. Forward params in `analyticsApi.getStats`

**File:** `frontend/src/services/api.js`

**Fix:** Change `getStats: () => api.get('analytics/stats/')` to `getStats: (params) => api.get('analytics/stats/', { params })`.

**Note:** The backend `DashboardStatsView` currently ignores the `range` param; this fix only makes the frontend pass it correctly. Backend time-range filtering can be added later as a feature.

### F2. Fix debounce no-op on page 1 in dashboard pages

**Files:** `DashboardProducts.jsx`, `DashboardOrders.jsx`, `DashboardCustomers.jsx`

**Problem:** The debounced effect only calls `setCurrentPage(1)`. When already on page 1, React does not re-trigger the `[currentPage]` effect, so the list is never refetched.

**Fix:** In the debounced effect, if `currentPage` is already 1, call the fetch function directly:

```jsx
useEffect(() => {
    const delayDebounce = setTimeout(() => {
        if (currentPage !== 1) {
            setCurrentPage(1);
        } else {
            fetchProducts();   // or fetchOrders / fetchCustomers
        }
    }, 500);
    return () => clearTimeout(delayDebounce);
}, [searchTerm, filterCategory]);   // deps vary per page
```

### F3. Fix storefront `Products.jsx` filter mismatch + URL params

**File:** `frontend/src/pages/Products.jsx`

**Fix:**
1. Import `useSearchParams` from `react-router-dom`.
2. Read `category` and `brand` from the URL on mount and seed the filters state.
3. Rename filter key `category` → `categories` (to match the DRF filter param).
4. Keep slug values for `categories` and `brand`.
5. Hoist `FilterSection` out of the component body; render it as a child component that receives `filters`, `categories`, `brands`, and `handleFilterChange` as props.
