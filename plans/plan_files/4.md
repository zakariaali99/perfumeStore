## Frontend Fixes

### F1. Fix all ESLint errors (HIGH)

**Goal:** Reduce `npm run lint` errors from 42 to 0 without changing application logic.

**Patterns fixed:**
- Removed unused destructured variables (e.g., `loading` from a store hook).
- Removed unused imports (`useNavigate` from `react-router-dom`).
- Removed unused named imports (`refreshError`, `get`).
- Rewrote unused catch parameters (`err`, `error`) as `catch { /* ignore */ }`.
- Added `/* ignore */` comments inside empty catch blocks to satisfy `no-empty`.

**Config adjustment:** Updated `frontend/eslint.config.js` so the linter recognizes common React conventions used in this codebase:
- `argsIgnorePattern: '^[A-Z_]'` — uppercase function arguments are typically component props like `icon: Icon` and are rendered as JSX.
- `varsIgnorePattern: '^[A-Z_]|^motion$'` — uppercase component variables and the `motion` namespace are rendered as JSX member elements (e.g., `<motion.div>`, `<Icon />`).

This avoids false-positive unused-variable reports for JSX that the current flat-config setup (without `eslint-plugin-react`) does not attribute correctly.
